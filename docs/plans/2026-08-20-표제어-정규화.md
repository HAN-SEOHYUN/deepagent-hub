# 표제어 정규화 — `contains_target` 이 정상 표제어를 떨어뜨린다

- 작성: 2026-08-20
- 대상: `word_example/checks.py` :: `contains_target()` (125행)
- 요청자: sb (첫 손님) — `docs/kb/40-consumers/sb.md`
- 추적: **#27** (Bug — 슬래시·placeholder 단어의 예문 생성이 항상 실패)
- 상태: **미착수** (2026-08-20 검증 리뷰 반영됨 — 아래 규칙 3·4 는 리뷰로 교정된 버전)

## 증상

sb 단어 775개 중 **3개**가 예문 생성에 항상 실패한다. 셋 다 BBC 정상 표제어이고
크롤러 문제가 아니다. 판정이 `대상 단어가 예문에 없다` 로 떨어져 재생성 루프를
소진하고, run 이 실패해 sb 는 `words.example` 을 NULL 로 남긴다.

```sql
-- sb 로컬 DB 실측 (2026-08-20)
SELECT id, english FROM words WHERE example IS NULL OR example='';
--  88  pay back / pay off / clear (debt)
-- 110  set someone up for something
-- 120  put (someone) in their place
-- 총 775 단어 / 예문 있음 772
```

## 원인

`_tokens()` 의 정규식은 `[A-Za-z][A-Za-z'-]*` 다. **구두점만 버리고 괄호·슬래시
안의 낱말은 그대로 남긴다.** 그래서 「대안 중 하나」와 「자리표시자」가 전부
**필수 낱말**로 둔갑하고, `contains_target` 이 그것들을 순서대로 요구한다.

| id | 표제어 | `_tokens` 결과 | 실제로 요구되는 것 |
|---|---|---|---|
| 88 | `pay back / pay off / clear (debt)` | pay, back, pay, off, clear, debt | 6개가 **순서대로** 한 문장에 |
| 110 | `set someone up for something` | set, someone, up, for, something | `someone`·`something` 이 **글자 그대로** |
| 120 | `put (someone) in their place` | put, someone, in, their, place | `someone` 이 글자 그대로 |

## 고치는 법 — `_tokens` 에 넣기 전에 표제어를 정규화

| # | 규칙 | 해결 |
|---|---|---|
| 1 | `…` / `...` 제거 | — |
| 2 | 괄호 그룹 `\([^)]*\)` 제거 | **120** |
| 3a | **공백 있는 ` / `** = 구 단위 대안 → **any-of**: 어느 구든 하나가 매칭되면 통과 | **88** |
| 3b | 공백 없는 `good/bad` = 낱말 단위 대안 → **any-of**: 어느 낱말이든 매칭되면 통과 | `set a good/bad example` — good 판이든 bad 판이든 통과 |
| 4 | 자리표시자 낱말 제거: `someone` `something` `somebody` `oneself` `one's` `sth` `sb` + **소유격 `their` `one's` → 임의 소유격(`my` `his` `her` `our` `your` `their`) 흡수** | **110**, **120** |

3a 와 3b 는 **다른 규칙**이다 (구 단위 vs 낱말 단위). 둘 다 **첫 것만 남기면 안 된다** —
프롬프트(`prompts.py`)는 어느 변형을 쓰라고 지시하지 않으므로 LLM 은 자유롭게 고른다.
첫 변형만 인정하면 `paid off` / `cleared his debt` 같은 **정상 예문이 다시 떨어진다**
(2026-08-20 규칙 프로토타입 실측: 88 의 3개 변형 중 1개만 통과, 120 의 소유격 치환
`put me in my place` / `put the intern in his place` 전부 FAIL).

**any-of 는 판정을 약하게 만들지 않는다** — 나열된 변형은 전부 그 표제어의 정당한 쓰임이다.

### ⚠️ sb 의 `_probe` 를 그대로 복사하면 안 된다

sb `app/services/agent.py` 에 비슷한 `_probe()` 가 있지만 **이 문제를 못 푼다.**
`develop`(212198f) 코드를 실제로 돌린 결과 (2026-08-20 재검증 — 5/5 동일):

```
'pay back / pay off / clear (debt)'  ->  'pay back  pay off  clear'      ← 안 고쳐짐
'set someone up for something'       ->  'set someone up for something'  ← 안 고쳐짐
'put (someone) in their place'       ->  'put in their place'            ← 고쳐짐
'pro- (something)'                   ->  'pro-'
'set a good/bad example'             ->  'set a good example'
```

3개 중 1개만 잡는다. `_probe` 는 규칙 3을 **낱말 단위(3b)로만** 하고 **규칙 4가 없다.**
그래도 됐던 이유는 `_probe` 가 **캐시 키 겸 프롬프트 힌트**일 뿐 판정 기준이 아니어서다.
허브는 3a 와 4를 더 얹어야 한다.

## 가드 — 느슨해지는 만큼 방어를 같이 넣는다

정규화는 판정을 **약하게** 만든다. 「대상 단어가 안 들어간 예문」을 통과시키기
시작하면 이 검사는 없는 것과 같다. `tests/test_word_example_checks.py` 에 추가:

- 완전히 무관한 문장은 **여전히 False**
  `contains_target("The weather is nice today outside.", "set someone up for something")`
- 정규화 후 남는 것이 없는 표제어(예: `(something)` 뿐)는 **False**
  `if not parts: return False` 가 받아주지만, **정규화가 전부 지우는 경로가 새로 생기므로**
  테스트로 못 박는다
- 기존 `contains_target` 테스트(함수 6개, 파라미터 케이스 포함 그 이상)가 그대로 통과 — 특히 **부분 문자열 거부**
  (`cat` 이 `category` 안에 있다고 통과시키지 않는다)

**뮤테이션 검증 필수** (`docs/kb/40-consumers/sb.md` 「sb 쪽 작업 규칙」):
정규화를 되돌리면 새 테스트 3건이 **빨개져야** 한다. 안 빨개지면 그 테스트는 없는 것과 같다.

## #27 과의 정합 (2026-08-20 리뷰)

이 플랜의 최초 버전(규칙 3 「첫 것만」·규칙 4 소유격 없음)은 #27 의 수정 방향·수용 기준과
어긋났다. 위 표는 교정본이며 #27 기준과 일치한다:

- #27 수용 기준: `contains_target("I paid off my debt.", "pay back / pay off / clear (debt)")` → True (any-of)

구현·검증은 #27 의 수용 기준 ↔ 검증 명령을 기준으로 한다. 이 문서는 설계 노트다.

## 함께 정할 것 — 접두사 표제어

`pro- (something)` 은 정규화하면 `pro-` 만 남는다. `_matches` 가 부분 문자열을
거부하므로 `pro-recycling` 을 못 잡는다. 지금 sb DB 엔 1건이고 그 예문은 수동
시드라 당장 안 터지지만, **다음 크롤에 또 나온다.**

| 안 | 내용 |
|---|---|
| a | 하이픈으로 끝나는 표제어는 부분 문자열 허용 (`pro-` ⊂ `pro-recycling`) |
| b | 접두사 표제어는 `contains_target` 검사 면제 |

정한 뒤 `docs/kb/00-project/decisions.md` 에 근거를 남긴다 — 안 남기면 몇 주 뒤
같은 논의를 처음부터 반복한다.
